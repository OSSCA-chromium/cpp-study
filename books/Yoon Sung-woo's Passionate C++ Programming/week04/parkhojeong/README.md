# Chrome에서 체크박스 하나를 클릭하면 무슨 일이 일어날까?

『윤성우의 열혈 C++ 프로그래밍』 4주차 · Chapter 04 클래스의 완성

‘기본 브라우저로 설정’ 옆의 체크 표시를 해제했다. 이 순간 컴퓨터의 기본 브라우저 설정도 바뀔까? 그렇다면 다시 체크했을 때 Chrome은 방금 바꾼 설정을 되돌려야 할까?

macOS와 Linux용 Chrome에는 일부 첫 실행 조건에서 이런 대화상자를 띄우는 코드가 있다. 이 창이 열리고, 사용자가 체크를 한 번 해제한 뒤 확인을 누른다고 해 보자. C++ 객체 하나가 만들어져 자기 상태를 기억하고, 다른 객체에 그 값을 알려 준 뒤 사라지는 과정을 화면에서 일어나는 순서대로 볼 수 있다.

## 창 하나를 누가 함께 만들까?

Chrome 안에서도 웹페이지와 브라우저 창은 서로 다른 곳에서 동작한다. 웹사이트가 페이지에 넣은 체크박스라면 그 페이지를 담당하는 렌더러 프로세스에서 클릭을 처리한다. 여기서 살펴볼 체크박스는 Chrome이 직접 띄운 창에 있다. 이 창을 만들고 사용자 입력에 반응하는 코드는 **브라우저 프로세스의 메인 스레드**, 흔히 말하는 UI 스레드에서 실행된다.

화면에는 창 하나만 보이지만 코드에서는 세 역할을 구분하면 읽기 쉽다. 창을 화면에 띄우고 닫는 일은 `Widget`이 맡는다. 그 창에서 무엇을 묻고 확인을 눌렀을 때 어떻게 처리할지는 Chrome의 첫 실행 대화상자 `FirstRunDialog`가 정한다. 대화상자는 네모 칸이 필요할 때 Chromium의 공용 UI 라이브러리인 **Views**에서 `Checkbox`를 가져다 쓴다.

이 구분은 실제 화면에서도 찾을 수 있다. 같은 대화상자에는 ‘기본 브라우저로 설정’과 사용 통계·오류 보고에 관한 선택지가 있다. 두 칸은 클릭하면 똑같이 체크되지만, 하나를 눌렀다고 다른 칸까지 바뀌지는 않는다. **클래스는 같은데 객체가 두 개**이기 때문이다. 체크하고 해제하는 코드는 공유해도 각 객체는 자기 선택값을 따로 갖는다.

## 창이 열리기도 전에 누가 체크했을까?

대화상자를 열 때 Chrome은 먼저 대화상자 객체를 만든다. 바로 이때 실행되는 C++ 함수가 **생성자**다. 생성자 안에서 ‘기본 브라우저로 설정’이라는 문구를 붙인 체크박스를 만들고, 그것을 대화상자의 자식으로 추가한다. Views에서 화면을 이루는 요소 하나를 *뷰*라고 하는데, 자식으로 추가한다는 말은 이 체크박스를 대화상자가 담고 있는 화면 요소 중 하나로 등록한다는 뜻이다.

체크박스 자체의 선택값은 처음에 거짓이다. 하지만 첫 실행 대화상자는 방금 만든 체크박스에 `SetChecked(true)`를 호출한다. 이 준비가 끝난 뒤 창이 화면에 나타나기 때문에 사용자는 빈 칸이었다가 체크되는 과정을 볼 필요 없이 처음부터 체크 표시를 보게 된다. 대화상자는 이때 `make_default_`라는 멤버에 체크박스를 가리키는 포인터도 저장한다. 나중에 확인 버튼을 눌렀을 때 두 칸 중 어느 쪽에 물어봐야 하는지 이미 정해 둔 셈이다. [체크박스를 만드는 코드](https://source.chromium.org/chromium/chromium/src/+/main:chrome/browser/ui/views/first_run_dialog.cc;l=108-110;drc=b54ea5764725c628b8ce7041d594cd509f2f569f)

## 네모 칸을 누르면 어디까지 바뀔까?

마우스로 네모 칸을 한 번 누른다. 창이 입력을 받으면 Views가 클릭한 위치에 해당하는 화면 요소로 이벤트를 전달한다. 이제 실행되는 코드는 첫 실행 대화상자의 설정보다 범위가 좁다. 클릭을 받은 체크박스 하나가 자기 값을 뒤집는다.

```cpp
SetChecked(!GetChecked());
```

괄호 안부터 읽으면 쉽다. 현재 선택값을 읽고, 참이면 거짓으로 바꾸어 다시 저장한다. 체크박스는 새 값에 맞춰 표시를 갱신하고, 화면 읽기 프로그램에도 선택 해제 상태를 알릴 수 있도록 접근성 정보를 갱신한다. 다른 체크박스는 그대로이고, 운영체제에 기본 브라우저를 바꿔 달라는 요청도 아직 일어나지 않았다. 한 번 더 누르면 같은 코드가 이번에는 거짓을 참으로 뒤집는다.

## 확인 버튼은 내가 무엇을 골랐는지 어떻게 알까?

이제 확인을 누른다. 앞선 클릭과 같은 UI 스레드에서 처리되지만 이번에 결정할 일은 다르다. 공용 버튼 코드가 확인 입력을 받으면, 그 선택을 어떻게 반영할지는 첫 실행 대화상자에 맡긴다. 대화상자는 처음 저장한 포인터를 통해 체크박스에 **지금 선택돼 있는지** 묻는다.

우리가 한 번 해제한 채로 확인했다면 답은 거짓이다. 대화상자는 기본 브라우저 설정 요청을 건너뛰고 창을 닫는다. 다시 체크한 뒤 확인했다면 답은 참이고, 이때 Chrome이 운영체제에 기본 브라우저 설정을 요청한다. 따라서 사용자가 체크를 몇 번 바꿨는지 대화상자가 기록할 필요도, 이전 클릭 때문에 운영체제 설정을 되돌릴 필요도 없다. **체크박스가 선택값을 기억하고, 대화상자가 확인 시점에 그 값의 의미를 해석한다.** [확인 버튼을 눌렀을 때 실행되는 코드](https://source.chromium.org/chromium/chromium/src/+/main:chrome/browser/ui/views/first_run_dialog.cc;l=128-133;drc=b54ea5764725c628b8ce7041d594cd509f2f569f)

## 창이 닫히면 체크박스 객체는 누가 정리할까?

화면에서 창이 사라지는 것과 메모리에 있던 C++ 객체를 정리하는 것은 코드에서 따로 살펴볼 문제다. 확인 처리를 마친 대화상자는 `Widget`에 창을 닫아 달라고 한다. 그런데 첫 실행 대화상자의 소멸자를 열어 보면 `= default`라고만 적혀 있다. 직접 만든 체크박스를 지우는 줄은 어디에 있을까?

생성자에서 했던 두 가지 일을 떠올려 보자. 대화상자는 체크박스를 **자식으로 추가**했고, 그 객체를 **가리키는 포인터를 저장**했다. 포인터가 있어서 나중에 선택값을 읽을 수 있다. 객체의 수명을 누가 책임지는지는 자식으로 추가하는 쪽에서 결정된다. 처음에는 `std::unique_ptr`가 새 체크박스를 소유한다. 대화상자가 이를 자식으로 받으면서 소유권, 곧 나중에 체크박스를 정리할 책임도 넘겨받는다. 생성자가 끝난 뒤에도 체크박스가 살아 있어 사용자 입력을 받을 수 있는 이유다.

대화상자 역시 Views의 화면 요소이므로, 소멸할 때는 기반 클래스인 `View`의 소멸자도 실행된다. 그 안에서 부모 뷰가 자식 목록을 순회하며 자신이 소유한 자식을 삭제한다. 우리가 눌렀던 체크박스의 소멸자가 호출되는 지점이 여기다. 첫 실행 대화상자는 ‘기본 브라우저로 설정’의 의미만 알면 되고, 자식 뷰들을 정리하는 일은 다른 화면 요소와 같은 코드를 쓴다. [부모 뷰가 자식을 삭제하는 코드](https://source.chromium.org/chromium/chromium/src/+/main:ui/views/view.cc;l=303-325;drc=b54ea5764725c628b8ce7041d594cd509f2f569f)
