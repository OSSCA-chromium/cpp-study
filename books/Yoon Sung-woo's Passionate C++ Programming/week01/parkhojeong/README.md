# 1주차 — Chapter 1, 2

『윤성우의 열혈 C++ 프로그래밍』의 Chapter 1, 2를 공부하고, 배운 개념을 Chromium 코드와 연결해 블로그 글로 정리했습니다.

## 블로그 글

### 1. [C++ 빌드 과정으로 이해하는 inline과 Chromium의 작성 지침](https://parkhojeong.github.io/blog/cpp-inline/)

- 전처리, 컴파일, 링크 과정과 헤더·소스 파일의 역할을 정리했습니다.
- 여러 소스 파일에서 같은 헤더를 포함할 때 함수의 중복 정의가 발생하는 이유를 재현하고, 정의를 `.cc`로 옮기는 방법과 `inline`을 사용하는 방법을 비교했습니다.
- 헤더 가드의 적용 범위와 `inline`의 언어 규칙, 실제 인라인 확장의 차이를 구분했습니다.
- Chromium의 실제 코드와 스타일 가이드를 살펴보고, 문법상 허용되는 코드와 프로젝트에서 권장하는 작성 방식을 구분했습니다.

### 2. [C++ 함수의 매개변수에 &와 const가 붙는 이유](https://parkhojeong.github.io/blog/cpp-reference/)

- 값 전달, 참조 전달, `const` 참조 전달에서 원본 변경 여부가 어떻게 달라지는지 실행 결과로 비교했습니다.
- 참조의 초기화와 대입을 구분하고, `const` 참조가 원본을 영구적으로 변경 불가능하게 만드는 것은 아니라는 점을 정리했습니다.
- 참조 전달이 항상 더 빠른 것은 아니라는 점과, 같은 타입의 기존 객체를 참조할 때 복사를 피할 수 있다는 점을 구분했습니다.
- Chromium의 `PathExists`와 `DeleteFile` 선언을 읽으며, `const` 참조 매개변수가 함수 전체의 부작용을 막는 것은 아니라는 점을 살펴봤습니다.
